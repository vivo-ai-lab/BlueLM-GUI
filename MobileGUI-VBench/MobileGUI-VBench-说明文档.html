1. 概述

MobileGUI-VBench 是一份面向移动端 GUI Agent 能力评测的基准测试题集，覆盖社交通讯、音乐电台、视频播放、购物优惠、旅游出行、交通导航、便捷生活、资讯阅读等多个真实生活场景，涵盖单应用与跨应用、单意图与多意图、显性指令与隐含意图指令等多种任务形态，用于评估 Agent 在真实手机 App 环境下的指令理解与执行能力。

数据文件：MobileGUI-VBench.xlsx（完整标注）、MobileGUI-VBench.jsonl（精简字段）

3. 标签定义

本节对 MobileGUI-VBench 使用的多维度标签进行定义说明，作为任务标注与结果分析的判定依据。标签体系共包含 6 个分类维度（指令类型 / 链路复杂度 / 应用范围 / 操作类型 / 指令清晰度 / 意图情况）和 2 个辅助字段（前置条件 / 理想澄清）。

3.1 指令类型

标签定义示例
Agent执行类指令信息完整、目标明确，Agent 可直接执行无需追问用户"帮我把QQ状态换成忙碌"
Agent-User交互类指令信息不足或存在多种合理执行路径，期望 Agent 主动向用户澄清后再执行"把我的QQ状态换成别的"（需澄清换成哪种状态）

3.2 链路复杂度

按完成该任务所需的预估操作步数划分（一次点击/输入/滑动计为一步）：

标签定义示例
简单≤ 5 步即可完成"打开网易云音乐"
中等6 ~ 10 步"在B站搜索科技类视频并播放"
复杂> 10 步，或涉及多页面深度跳转"在小红书找到评分最高的咖啡店并收藏笔记"

3.3 应用范围

标签定义示例
单应用任务全程在单个 App 内完成"在QQ音乐中播放我喜欢的歌曲"
跨应用任务需要在 ≥2 个 App 之间切换或数据流转"把微信里朋友发的定位在高德地图中打开"

3.4 操作类型

标签定义涉及的基础 UI 动作
基础操作仅使用最常见的 GUI 交互点击、文本输入
进阶操作涉及更复杂的手势或控件操作滑动、拖拽、长按、双击、缩放、滚动定位

3.5 指令清晰度

标签定义示例
显性指令指令中明确给出对象、动作、参数等关键信息，无需推断"把微信里张三的聊天置顶"
隐含意图指令指令未明确说出真实意图，Agent 需要基于常识或上下文推断"好久没上QQ了，看看朋友们最近都在发些什么动态"（隐含意图：查看好友动态）
模糊指令指令缺少关键参数、或存在多种合理解读，Agent 需进一步澄清"帮我搜一下那个电影"（需澄清：哪部电影？在哪个平台搜？）

3.6 意图情况

标签定义示例
单意图一条指令只包含一个独立任务"打开网易云音乐播放我喜欢的歌单"
有依赖多意图一条指令包含多个任务，且任务间存在条件依赖或数据传递关系（必须先完成 A 才能完成 B）"在高德地图搜附近的火锅店，然后把最近一家发给微信里的张三"（B 依赖 A 的结果）
无依赖多意图一条指令包含多个任务，但任务间相互独立、可并行执行"把QQ状态换成忙碌，同时打开网易云音乐"

3.7 前置条件（precondition）

执行任务前需要满足的环境状态或账户状态。该字段为空表示任务无特殊前置要求。

示例：

  • "QQ状态当前不为忙碌"（用于"把QQ状态换成别的"任务，否则变更无意义）
  • "用户已登录抖音账号"
  • "已开启定位权限"

3.8 理想澄清（clarification_requirement）

针对 Agent-User 交互类任务，期望 Agent 主动向用户发起的澄清问题或确认行为。该字段是评估 Agent 主动交互能力的核心依据。

示例：

  • "询问哪个（任意一个）"——对应"把我的QQ状态换成别的"
  • "确认目的地是家还是公司"——对应"导航回家"
  • "询问出发日期"——对应"帮我订一张去北京的高铁票"

12. 小结

MobileGUI-VBench 数据集共 150 条任务，覆盖 40 种主流移动应用及 8 大生活场景，任务设计兼顾单应用与跨应用协同、单意图与多意图链路、显性指令与隐含/模糊意图理解等多维度能力考察，可用于全面评估移动端 GUI Agent 的场景泛化能力与复杂指令理解执行能力。
